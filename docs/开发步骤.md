# 截图记账（暂名 SnapLedger）开发步骤

> 这份文档负责定下「步骤」和「每个文件夹管什么」，以及课程要的 IC-PBL 问题分析。具体数值（类别、配色、文案）写在代码的配置里，不影响这里的结构。

## 零、核心设定（2026-10-28 定）

- **一句话**：付款以后把截图分享给应用，自动识别成一笔账；不同货币自动换算；每个月生成一组故事卡片，回顾这个月的钱花在哪里。
- **用户**：同时用好几个付款应用、好几种货币的年轻人。先以自己和身边同学为对象。
- **只做单机**：不做账号和云同步，数据只存在手机里，可以导出。
- **三种语言**：中文、韩文、英文。

## 一、IC-PBL 问题分析

格式和 Activity 2 交的「과제 수행 계획서（문제 분석지）」一样，第 11 周的 Activity 3 开始用这个新题目。

**问题**：年轻人很少坚持记账。付款分散在银行卡、Toss、KakaoPay、微信、支付宝等好几个应用里，还经常涉及两种货币，手动记账太麻烦，记几天就放弃，到月底不知道钱花在哪里。

**가설/해결안（Ideas）**
- 截图分享就记账：在手机本地识别截图里的金额、日期、商家，弹窗确认一下就存好。
- 多币种：每一笔按当天汇率换算成主货币来统计。
- 月度故事卡片：把「看账」做成像年度总结一样有意思、愿意分享的事。
- 消费地图和超支提醒：知道钱花在哪里、什么时候该停一停。

**알고 있는 사실（Facts）**
- OECD/INFE 2023 年的成人理财素养调查覆盖 39 个国家和地区、6.8 万多名 18～79 岁的成年人，平均分只有 60 分（满分 100）。
- 各个付款应用付款后都有完成页面，截图很方便。
- 用户自己的付款截图（2026-10-28 收集）都是列表：银行 App 的交易明细、微信「微信支付」里的付款通知，一张里有好几笔，不是单笔的付款完成页。
- ML Kit 文字识别 v2 在手机本地支持中文和韩文，不用联网，也不用相机（可以识别相册和分享过来的图片）。
- Frankfurter 汇率接口免费、不需要密钥，有韩元和人民币。
- Spotify Wrapped 从 2016 年起每年做年度回顾，被大量用户自发分享到社交媒体，说明回顾卡片这种形式让人愿意看、愿意分享。

**더 알아야 할 사항（Learning Issues）**
- 各个付款应用截图的文字排版，怎样从识别出的文字里可靠地找出金额、日期、商家；列表截图里怎样把每一笔分开。
- Room 数据库的表怎么设计，怎样按月统计。
- 用 Canvas 画圆环图、趋势图、日历热力图。
- Compose 动画和故事卡片（点一下翻下一张、顶部进度条）。
- 怎样接收其他应用分享过来的图片（Intent），怎样把图片分享出去（FileProvider）。
- 定位权限、地图、WorkManager 定时提醒。
- 汇率的缓存，以及断网时怎么办。

**앞으로의 계획（Action Plan）**：见下面的步骤和时间表。

| D20 | 超支提醒：设置里填每月预算（主货币），本月支出跨过 80% 和 100% 时各提醒一次（App 里的提示条），账本的本月卡片显示预算进度 | 记账时人就在 App 里，用提示条比通知直接；改小、删除不提醒，免得重复 |

| D24 | 类别继续用表情符号；底部菜单、按钮、启动图标自己画成矢量图，不加图标库 | 表情是彩色的，三种语言都看得懂；只用到几个图标，不值得加一个很大的库 |

## 三、文件夹分工

```
SnapLedger/                   整个项目（放在课程文件夹里）
├─ app/                       代码和资源
├─ docs/                      开发步骤.md，以后的报告、PPT 和讲稿也放这里
└─ gradle/ build.gradle.kts settings.gradle.kts …   构建配置，平时不用动

app/src/main/java/com/codefield/snapledger/
├─ model/      数据类：一笔账、类别、货币、金额、识别结果、月度统计结果
├─ logic/      记账规则（纯 Kotlin）：解析识别文字、货币换算、月度统计、回顾卡片的内容
├─ data/       存档：Room 数据库、Repository、设置
├─ remote/     汇率接口
├─ system/     文字识别（ML Kit）、定位、通知和定时任务、分享图片、导出文件
├─ ui/
│  ├─ SnapLedgerApp.kt  页面导航和底部菜单
│  ├─ common/  主题、通用组件
│  ├─ ledger/  账本（列表、记一笔）
│  ├─ stats/   统计图表
│  ├─ review/  月度回顾卡片
│  ├─ map/     消费地图
│  └─ settings/ 设置
└─ MainActivity.kt   只负责启动界面

app/src/main/res/values/      默认文字（英文）
app/src/main/res/values-ko/   韩文
app/src/main/res/values-zh/   中文
app/src/test/                 规则的单元测试
```

### 依赖规则

- `model` 不依赖任何文件夹，其他文件夹都可以用它。
- `logic` 只依赖 `model`。
- `data`、`remote` 只依赖 `model`。
- `system` 依赖 `data`、`logic` 和 `remote`（下载汇率存进数据库的 `RateUpdater` 在这里）。
- `ui` 通过 ViewModel 调用其他文件夹，界面不直接碰数据库和网络。

## 四、步骤

每一步做完都要达到「完成标准」，然后提交一次 Git。

**进度**
- 第 1 步：完成（2026-10-28）。
- 第 2 步：完成（2026-10-28）。
  - **截图文字解析**：给每个像金额的数字打分（货币符号、减号、「결제금액／实付」这类词、字的大小加分；「잔액／余额／누적」减分），日期支持韩、中、英几种写法，商家名优先取金额上面那一行或「가맹점／商户全称／商品说明」后面的字。
  - **其他规则**：按关键词猜类别；按当天汇率换算（周末用之前最近一天的汇率）；按月统计（总额、各类别、每天、常去的店、最大一笔、和上月比）。
  - **测试**：24 个单元测试全部通过，样例照着 KakaoPay、Toss、韩国银行卡短信、微信支付、支付宝的排版写。
- 第 3 步：完成（2026-10-28）。Room 数据库（账目、按日期存的汇率）、Repository、设置（主货币）。在模拟器上验证过：强行关掉 App 再打开，账目都还在。
- 第 4 步：完成（2026-10-28）。
  - **账本页**：按天分组、本月支出（外币笔数单独提示）。
  - **记一笔对话框**：金额、货币、商家、类别、日期和时间的选择对话框、备注；改一笔，删除前确认，删除后能撤销。
  - **验证**：在模拟器上验证过旋转屏幕时对话框里的输入不丢；中文和韩文界面都点过。33 个单元测试通过。
- 第 5 步：完成（2026-10-29）。用户自己的截图放在 `samples/`（这个文件夹不提交到 Git）。
  - **入口**：账本页右下角「识别截图」（系统照片选择器，一次最多 20 张，不用申请相册权限）；在别的应用里「分享」给本应用（一张或多张）。原来的「+」变成上面的小按钮，用来手动记一笔。
  - **识别**：存副本 → 韩文、中文模型各读一遍 → 按位置拼行（同一行两头的「결제금액」和「6,500원」拼在一起）→ 挑读得懂的一份 → 用第 2 步的规则解析。截图里没有日期时，用文件名里的截图时间（「Screenshot_20261028_143205.jpg」）。
  - **确认对话框**：就是「记一笔」对话框，已经填好；上面有截图小图（点了看大图）；找到几个金额时可以点着换；没找到金额、可能记过了会有提醒。多张时标题显示「1/5」。
  - **规则补充**：和英文连着的数字不算金额（「GS25」「5G」）；余额这类扣了分的数字不给用户挑；行首行尾的竖线去掉。
  - **验证**：自己画了 5 张假付款页（KakaoPay、Toss、微信、支付宝的样式，加一张聊天截图）在模拟器上测：金额、商家、时间、类别都对，聊天截图提示没找到金额；从「文件」应用分享进来能用；旋转屏幕、进程被系统关掉后再回来，队列和输入都还在；中文、韩文界面都看过。识别 5 张大约 4 秒。
  - **用户截图验收**：用户手上只有 2 张付款截图，但都是列表，一共 8 笔（银行流水 6 笔，其中 1 笔退款；微信支付通知 2 笔），按笔数算超过了完成标准的 5 笔。按原来「一张一笔」的做法，流水那张把账户余额当成了金额；微信那张因为返回箭头被认成日文「く」，货币变成了日元，电量「73」和卡号尾号也混进了候选金额。
  - **列表截图（D15）**：同一种格式重复好几次、金额差不多大的就是列表（流水看正负号，付款通知看货币符号）；两个金额之间的行按上下空隙分给两边（同一笔里的行挨得近）；没写日期的往上找「10월 27일」这种分组日期，只写了时间的算截图那天。确认时是勾选列表，一次保存好几笔。
  - **规则补充（用户截图以后）**：状态栏（最上面以时钟开头的一行）里的数字不算金额；括号里的卡号尾号不算；「원」认成「2」时（「137,1892」）只取逗号那部分；有两个以上假名、而且假名不比汉字少太多才算日文；「출금가능금액」算余额；「使用…储蓄卡支付」这类付款方式不当商家；图标认成的「②」从名字里去掉。
  - **验证（用户截图）**：两张截图在模拟器上全部识别对（5 笔支出、2 笔人民币，退款和余额没有列进来）；取消勾选、点开一笔修改、转屏、进程被系统关掉后回来都正常；同一张流水再导入一次，记过的 4 笔都提示「可能已经记过」、默认不勾；中文、韩文界面都看过。
  - **测试**：57 个单元测试通过。包括把模拟器上 ML Kit 真实读出的文字（包括认错的字，比如「원」读成「l」「2」、「¥」没读出来）原样写成的测试；用户的两张截图也写成了测试，金额、余额、时间、卡号都改过。
  - **待办**：APK 有 58MB，主要是 ML Kit 给 4 种 CPU 各带了一份程序；第 10 步让正式版只打包手机用的 arm64，能降到 20MB 左右。英文里「%d entries」这类要改成复数写法（lint 提示 4 处），也放到第 10 步。（第 10 步都做了，正式版 16MB。）
- 第 6 步：完成（2026-10-29）。
  - **下载汇率**：Frankfurter（`api.frankfurter.dev/v1`，欧洲央行每个工作日公布的参考汇率）。打开 App 和每次回到前台时补一下：第一次取最早一笔账前一周到最新；记了比已有汇率更早的账时补上那段；隔 6 小时才看一次有没有新汇率。设置里可以「立即更新」。只申请了联网权限，截图识别照样不联网。
  - **断网**：什么也不存，账本、统计接着用存下的汇率；设置里提示「没能更新」。
  - **设置页**：选主货币（韩元、人民币、美元、日元、欧元），统计、回顾、手动记账的默认货币跟着变；显示最新汇率的日期和「1 CNY = ₩201.08」「1,000 KRW = ¥4.97」这样的汇率。
  - **账本**：外币那一笔下面小字写「≈ ₩9,049」（按付款那天的汇率）。
  - **验证**：模拟器上第一次打开就下载好了汇率，以前没算进总额的人民币几笔都算进去了；换成人民币后总额和每笔的换算都对；关掉网络点「立即更新」提示失败、汇率还在；断网时把 App 彻底关掉再打开，换算照常；恢复网络后提示消失；中文、韩文界面都看过。
  - **测试**：77 个单元测试通过。新加的有：要下载哪几段汇率、显示用的汇率、用接口真实返回的 JSON 测解析、断网时已有的汇率不受影响。
- 第 7 步：完成（2026-10-29）。
  - **统计页**：上面左右箭头翻月份（最早翻到第一笔账那个月，最晚到这个月）；支出合计、笔数、比上个月多花或少花多少。
  - **图表（都用 Canvas 画）**：分类圆环（按金额从大到小，旁边是图例和百分比）；每天的柱状图（今天换个颜色，标出花得最多的一天）；消费日历（颜色越深花得越多，分 4 级；点一天显示那天的金额和笔数；一周从周几开始跟着界面语言，中文从周一，韩文从周日）；常去的店和最大的一笔。换月份时图表从 0 长出来。
